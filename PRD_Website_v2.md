# PRD: NEUROGUT website v2 (Parkinson's + Schizophrenia) with version toggle

**Owner:** Yashvi B. Naik · **Date:** 28 Oct 2026 · **Repo:** `C:\Major_project_Neuro_Gut` (branch `main_website_4`)

## 1. Goal
A single website with a **version toggle**:

| Version | Content | Status |
|---|---|---|
| **Classic (v4)** | The existing Depression & Anxiety platform: login, dashboard, analysis, patients, reports, benchmarks, admin | unchanged; restyled only |
| **NeuroGut v2** | Parkinson's disease (PD) and schizophrenia (SCZ) research results: cohorts, preprocessing, model benchmarks (internal + external), top microbial signals, PD vs SCZ comparison | new |

Both versions get the new design: a **white** base, **cobalt** primary and a **teal-green** accent.

## 2. Users
- **Clinicians, researchers and admins:** the existing roles and login apply to both versions.
- **Project reviewers and examiners:** read v2 to see what the two new disease models achieve and how honestly they are validated.

## 3. Tech stack (kept from the existing app; no new runtime dependencies)
| layer | choice |
|---|---|
| Frontend | Next.js 16 (App Router) + React 19 + TypeScript, existing `src/app/(app)` route group, so v2 shares login and the sidebar |
| Styling | Tailwind CSS 4 + the existing CSS design tokens in `globals.css`. The palette changes at token level, so every page is restyled at once |
| Charts | Plotly (`react-plotly.js`, already installed) |
| v2 data | **Static JSON** in `neurogut-frontend/src/data/v2/` generated by `scripts/export_v2_data.py` from the research outputs. No backend change; works offline; rebuildable |
| Backend | Existing FastAPI + SQLite, unchanged (Classic only) |
| Research code | `research/Neurogut schizophrenia/`: `scz-microbiome-data` (retrieval + profiling), `scz-ml` (training, `run_all.bat`), `external_repos/pd_repo` (PD pipeline clone). Large data is git-ignored |
| Deploy | Existing Docker + Nginx, unchanged |

## 4. Functional requirements
- **FR-1 Version toggle:**
  - A segmented "Classic | NeuroGut v2" switch sits at the top of the sidebar on every page.
  - Switching goes to `/dashboard` (Classic) or `/v2` (v2).
  - The active version is derived from the URL, so deep links and the back button stay correct.
  - The last choice is remembered (localStorage) and used after login.
- **FR-2 v2 navigation:** the sidebar shows v2 items while on `/v2/*`: Overview, Schizophrenia, Parkinson's, Methods.
- **FR-3 Overview (`/v2`):**
  - one card per disease with the headline internal and external ROC-AUC, cohort size and studies;
  - a PD vs SCZ comparison chart;
  - a short "what this means" box (honest limits).
- **FR-4 Schizophrenia (`/v2/schizophrenia`):**
  - cohort table (study, country, platform, HC/SCZ);
  - final model (E6) benchmarks: internal and leave-one-study-out tables per model;
  - per-held-out-study bar chart;
  - experiment comparison (E1–E8) chart;
  - top-20 features chart (direction coloured);
  - checks (batch signal, covariate-only, Xu).
- **FR-5 Parkinson's (`/v2/parkinsons`):**
  - nested-CV fold results per model (v5);
  - ablations (covariate-only, constipation dropped, species level, pathway collapsed, constipation-stratified);
  - headline internal and external numbers as reported by the PD team.
- **FR-6 Methods (`/v2/methods`):**
  - data retrieval → QC → MetaPhlAn 3 → harmonisation → cross-study feature selection → models → validation, as a step list;
  - limitations;
  - links to the PRDs in `research/`.
- **FR-8 Predictions, like Classic (added 29 Oct 2026):**
  - **New Prediction (`/v2/predict`):**
    - choose Schizophrenia or Parkinson's;
    - link a patient (optional) and a collection date;
    - **enter values** (relative abundance % of the model's 30 taxa) or **upload**: a CSV (one row per sample, template downloadable) or a raw MetaPhlAn profile / merged table.
    - The result card shows:
      - the profile score (0–100 %) and a risk tier (Low < 35 %, Moderate, High ≥ 65 %);
      - above/below the validated decision threshold;
      - the per-model breakdown (RF, XGBoost, Elastic Net);
      - the six taxa that move the score most, against healthy medians.
  - **Prediction History (`/v2/history`):** every v2 prediction for the hospital, filterable by disease; click a row for its full result.
  - **Backend:** `neurogut-backend/api/predict_v2.py` (`/api/v2/models`, `/api/v2/predict`, `/api/v2/predict/csv`, `/api/v2/templates/{disease}`, `/api/v2/predictions`). Results are stored in the new `v2_predictions` table, scoped to the hospital, and every run is audit-logged (`PREDICTION_RUN`). Upload rows whose `patient_code` matches a patient are linked to them.
  - **Models:** `neurogut-backend/models/v2/{scz,pd}.joblib`, built by `research/.../scz-ml` → `python -m sczml.deploy`.
    - The research models need a whole cohort (per-study scaling), so they cannot score one patient. The deploy models instead use log10(% + 0.01) of 30 taxa (species/genus/family) chosen by cross-cohort consistency, with RF + XGBoost + Elastic Net (no CatBoost, so they load in the backend venv).
    - The whole procedure is cross-validated:
      - **SCZ:** internal AUC 0.706, leave-one-study-out 0.624 (Li 0.56, Thirion 0.64, Zhu A 0.56, Zhu B 0.73).
      - **PD:** 5-fold AUC 0.722 (single cohort, so no external estimate).
    - Decision thresholds are Youden-optimal on out-of-fold predictions (SCZ 0.52, PD 0.58).
  - **Demo files:** `data/v2_examples/` holds `scz_example.csv` and `pd_example.csv` (training samples), and `scz_metaphlan_profile_Xu_heldout.tsv` (5 Xu cases never used in training).
- **FR-7 Data provenance:** every v2 number comes from the generated JSON, which records its source file and generation date (shown in the page footer).

## 5. Design
- **Tokens:**
  - white surfaces (`#FFFFFF` / `#F7F9FC`);
  - **cobalt** primary `#0047AB` (hover `#003A8C`, light `#E8EFFA`);
  - **teal-green** accent `#0F9D8A` (light `#E6F6F3`);
  - text `#0F1B2D` / `#5B6779`.
- **Use:** cobalt is for navigation, primary buttons and SCZ/series 1; teal for success, highlights and PD/series 2.
- **Unchanged:** the risk colours (green/amber/red) keep their clinical meaning.
- **Look:** cleaner cards (1 px border, soft shadow, 12 px radius), a subtle cobalt→teal gradient strip on the logo and the active nav, tabular numbers in tables.
- **Accessibility:** text contrast ≥ 4.5:1 on white; charts never rely on colour alone (labels and legends).

## 6. Non-functional
- Classic pages keep working exactly as before (same routes, API calls and roles).
- No new npm dependencies; `npm run build` passes.
- v2 pages load from static data: no API needed.
- Token and effort budget: v2 reuses the existing layout, card and table CSS classes, with one shared chart and table helper file.
