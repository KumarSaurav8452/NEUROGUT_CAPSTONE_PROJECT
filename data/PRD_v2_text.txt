1.  Project Overview & Enhancement Context


1.1  What is NEUROGUT?
NEUROGUT is an AI-powered clinical decision support platform that analyzes gut microbiome composition to predict neuropsychiatric conditions — specifically Depression and Anxiety — via the Gut-Brain Axis (GBA). It is designed as a hospital-facing SaaS tool enabling clinicians, gastroenterologists, and psychiatrists to submit a patient's microbiome sample data and receive a multi-label probability prediction, biomarker explanation, and clinical risk report.

4.2  Report Generation — Technical Spec

Use WeasyPrint for HTML-template-based rendering (supports complex layouts and CSS), with embedded Plotly chart images (PNG via kaleido).
All charts rendered server-side via plotly.io.to_image() and embedded as base64 PNG in the HTML template before PDF conversion.
Executive narrative generated by rule-based template engine using prediction thresholds and taxon values (no LLM dependency — deterministic and auditable).
Longitudinal section conditionally rendered only if patient has >= 2 prior analyses in DB.
Cohort benchmark uses anonymized aggregate computed nightly and cached in Redis (new dependency for v2.0).
Report SHA-256 hash stored in reports table; verifiable by admin via /audit.


5.  New Feature Specifications  (v2.0)


5.1  Longitudinal Patient Tracking
Patients with multiple sample analyses now have a dedicated longitudinal view on their profile page.

Frontend: /patients/[id] page gains a new 'Trend' tab with a Recharts LineChart (Depression prob, Anxiety prob, date on X-axis).
Frontend: Microbiome Evolution Heatmap — taxa on Y-axis, visit dates on X-axis, abundance colour scale.
Backend: GET /api/patients/{id}/trend returns ordered array of { sample_date, depression_prob, anxiety_prob, risk_tier } for all analyses.
Alert: if trend shows 3 consecutive increases in depression_prob, flag patient as 'Deteriorating' in dashboard.
PDF: Longitudinal section auto-included in report when trend data exists.

5.2  Cohort Benchmarking
Allows clinicians to see how a patient compares against the broader hospital population segmented by risk tier.

Nightly background job (Celery / APScheduler) computes per-taxa percentile distributions grouped by risk_tier — stored in cohort_benchmarks table.
GET /api/benchmarks returns { taxon, tier, p25, p50, p75, mean, std } for all 13 taxa × 4 tiers.
Results page gains 'Cohort Comparison' panel: box plots per taxon, patient value overlaid as orange dot.
Benchmarks page (/benchmarks) shows population-level distribution charts for research use.
All benchmark data is de-identified; raw patient values are never exposed in aggregate APIs.

5.3  Notification & Alert System
Automated alerts ensure clinicians are notified promptly when a high-risk result is produced.

Alert trigger rules (configurable per hospital via /admin/settings): Comorbid = always alert; High Risk single condition = alert if probability > configurable threshold (default 0.75).
In-app alerts: banner on dashboard + badge on /alerts page. Mark as resolved with notes.
Email alerts: SendGrid / SMTP. Template includes: patient code, risk tier, prediction probabilities, link to results page.
Backend: POST /api/alerts creates alert record; GET /api/alerts returns paginated alert history.
Alert escalation: if alert unresolved after 48h, escalate to Hospital Admin.

5.4  Audit & Compliance Log
HIPAA-grade audit trail for every significant data event in the system.

New audit_logs DB table: id, user_id, action (ENUM), resource_type, resource_id, ip_address, user_agent, timestamp.
Logged actions: LOGIN, LOGOUT, PATIENT_VIEW, SAMPLE_SUBMIT, PREDICTION_RUN, REPORT_GENERATE, REPORT_DOWNLOAD, USER_INVITE, SETTINGS_CHANGE, DATA_EXPORT.
GET /api/audit — admin-only, paginated, filterable by user/action/date range.
/audit page: tabular view with filters, CSV export for compliance submissions.
Audit records are immutable — no DELETE endpoint; retention policy configurable (default 7 years).

5.5  Prediction Confidence Bands
Clinicians need to understand not just the probability, but how certain the model is — essential for high-stakes clinical decisions.

Method: Bootstrap resampling over 100 iterations of the stacked ensemble to compute ±95% CI around depression_prob and anxiety_prob.
Backend: /api/predict response gains depression_ci_low, depression_ci_high, anxiety_ci_low, anxiety_ci_high fields.
Frontend: RiskCard component updated — probability gauge now shows CI range as a lighter band around the pointer.
UI copy: 'Depression Risk: 72% (CI: 64%–79%)' — educates clinicians on model uncertainty.
PDF: Confidence bands shown on prediction summary section with brief explanation of methodology.
